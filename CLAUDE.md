# CLAUDE.md

Guidance for AI assistants (and humans) working in this repository.

## Project overview

**MedFix Pro** (`medfix-pro2`, UI brand name **KJST**) is a medical-device
service management web app for tracking hospital customers, their medical
devices, service requests/history, technicians, and a spare-parts catalog with
pricing/deal history. The UI and domain language are **Korean**.

It is a single deployable FastAPI application that serves both a JSON REST API
(`/api/v1/...`) and server-rendered HTML pages (Jinja2 templates + a vanilla-JS
frontend). There is no separate frontend build step.

## Tech stack

- **Backend:** FastAPI 0.115, Uvicorn, SQLAlchemy 2.0 (typed `Mapped` / `mapped_column`), Pydantic v2
- **Templating:** Jinja2
- **Database:** SQLite (`medfix.db`, created in the working directory at startup)
- **Frontend:** Plain HTML/CSS/JS (no framework, no bundler) under `static/` and `templates/`
- **Excel import:** `openpyxl` (see the dependency gotcha below)
- **Python:** 3.11 (per `render.yaml`)

## Running locally

```bash
pip install -r requirements.txt
pip install openpyxl          # required for parts Excel import but MISSING from requirements.txt
python run.py                 # serves on http://0.0.0.0:8000 with --reload
```

`run.py` launches `app.main:app`. On startup the `lifespan` handler calls
`Base.metadata.create_all()` (auto-creates tables — there are **no migrations**)
and runs `app.seed.seed_data()`, which inserts demo customers/devices/etc. only
if the `customers` table is empty.

There are currently **no tests, no linters, and no formatter config** in the repo.

## Architecture & layout

Standard layered structure under `app/`. Each domain entity has a parallel file
in each layer:

```
app/
  main.py            # FastAPI app: lifespan (create_all + seed), CORS, static mount,
                     # router registration (prefix="/api/v1"), and HTML page routes
  database.py        # engine, SessionLocal, Base (DeclarativeBase), get_db() dependency
  seed.py            # idempotent demo-data seeding
  models/            # SQLAlchemy ORM models (one file per entity)
  schemas/           # Pydantic v2 request/response models
  crud/              # DB access functions (the only place that touches the ORM/session)
  routers/           # FastAPI APIRouters (HTTP layer; depends on crud + schemas)
  utils/excel_parser.py  # parses uploaded parts spreadsheets

api/index.py         # Vercel entrypoint: `from app.main import app`
run.py               # local dev entrypoint (uvicorn, reload, port 8000)
templates/           # Jinja2 pages; all extend base.html
static/css/          # main.css, components.css, forms.css
static/js/           # shared (api.js, utils.js, components.js) + one file per page
render.yaml          # Render deployment config
vercel.json          # Vercel deployment config
```

**Request flow:** `router` → `crud` → `model` → DB, with `schemas` validating
input and shaping output. Routers should not query the ORM directly; put DB
logic in `crud/`. (A couple of existing routers inline small queries — follow
the layered pattern for new code.)

| Model | Table | Domain (KR) |
|-------|-------|-------------|
| `Customer` | `customers` | 고객/병원 |
| `Device` | `devices` | 의료기기 |
| `Technician` | `technicians` | 기술자 |
| `ServiceRequest` | `service_requests` | 서비스 요청 |
| `ServiceHistory` | `service_history` | 서비스 이력 |
| `Part`, `PartDeal`, `PartMoveLog` | `parts`, `part_deals`, `part_move_log` | 부품관리 |

`Part` 1—N `PartDeal` (cascade delete).

## Key conventions

### Backend
- **SQLAlchemy 2.0 typed style:** declare columns with `Mapped[...]` and
  `mapped_column(...)`. Optional columns use `Mapped[str | None]`.
- **Timestamps:** `created_at` uses `default=datetime.now`; `updated_at` adds
  `onupdate=datetime.now`.
- **Status/enum fields are Korean string literals**, not enums — e.g. device
  `status` defaults to `"정상"`, service request `status` defaults to `"접수"`
  (접수 → 배정 → 진행중 → 완료), priority `"보통"`. Reuse existing literal values.
- **Auto request numbers:** `ServiceRequest.request_number` is generated by a
  `before_insert` SQLAlchemy event in `models/service_request.py`, formatted
  `SR-YYYYMMDD-NNN` (per-day sequence). Don't set it manually.
- **CRUD return contract:** create/update return the ORM object or `None` if
  not found; delete returns `True` (ok) / `False` (not found) / `None`
  (blocked, e.g. customer still has devices). Routers translate these into
  `404`/`409` `HTTPException`s with **Korean** `detail` messages.
- **Schemas (Pydantic v2):** per entity, define `*Base`, `*Create`,
  `*Update` (all-optional for partial updates), `*Response`
  (`model_config = {"from_attributes": True}`), and a `*ListResponse`
  (`items/total/page/size/pages`).
- **List endpoints** are paginated via `page`/`size` `Query` params (with bounds)
  and an optional `search`; responses include a computed `pages` count.
  Several routers serialize rows with a dict comprehension over
  `obj.__table__.columns` and then add computed fields (e.g. `device_count`).
- **Routers:** each `APIRouter` sets its own `prefix` and a Korean `tags`
  label; all are mounted under `/api/v1` in `main.py`. Page (HTML) routes live
  in `main.py` and return `TemplateResponse`.

### Frontend (`static/js/`)
- **No framework/bundler.** Scripts are loaded via `<script>` tags in
  `base.html` (`utils.js`, `api.js`, `components.js`) plus a per-page script in
  each template's `{% block scripts %}`.
- **All API calls go through `apiFetch(path, options)`** in `api.js`, which
  prefixes `/api/v1`, sets JSON headers, and throws `Error(detail)` on non-OK
  responses. Don't call `fetch` directly.
- **Shared UI helpers** live in `components.js`: `showToast`, `showModal` /
  `hideModal`, `showConfirm`, `showSidePanel` / `hideSidePanel`, `renderTable`,
  `renderPagination`, `initTabs`. `utils.js` has formatters (`formatDate`,
  `formatDateShort`, `statusBadge`, `priorityBadge`, `debounce`, `escHtml`).
  Reuse these instead of hand-rolling DOM/markup.
- Each page (`customers.js`, `devices.js`, …) follows the same pattern:
  `load<Entity>()` to fetch+render, `open/showCreate`, `openEdit`, `delete`,
  and a `<entity>Form(...)` builder. Templates: `base.html` is the shared shell
  (sidebar nav, modal, side panel, toast container); each page extends it.

### Naming / language
- Code identifiers are English; user-facing strings, API `tags`, and error
  `detail` messages are **Korean**. Match the surrounding language when adding
  features.

## Deployment

- **Render** (`render.yaml`): web service, `pip install -r requirements.txt`,
  start `uvicorn app.main:app --host 0.0.0.0 --port $PORT`.
- **Vercel** (`vercel.json`): routes static assets to `/static/...` and
  everything else to `api/index.py` (`@vercel/python`), which imports the same
  `app`.
- **Note:** SQLite is file-based and ephemeral on these platforms — data does
  not persist across deploys/restarts and the DB is re-seeded. Treat persistent
  storage as out of scope unless explicitly migrating to a managed DB.

## Known gotchas

- **`openpyxl` is imported (`utils/excel_parser.py`, `routers/parts.py`) but is
  NOT in `requirements.txt`.** The `/api/v1/parts/seed-excel` endpoint will fail
  with an import error until it's installed. If you touch parts import, add
  `openpyxl` to `requirements.txt`.
- No migrations: schema changes rely on `create_all`, which **won't alter
  existing tables**. Changing a model requires recreating `medfix.db` locally
  (it's gitignored). Plan accordingly for any persistent-DB migration.
- The DB file (`medfix.db`) and `.env` are gitignored.
